Second Look_IBM Z Datathon 2026 Project1
Why this projectBangladesh → the United States

I grew up in Bangladesh watching floods take homes. The second loss came later, on paper.

Families without a deed, a lease or a utility bill in their own name get turned away from aid. It happens everywhere. The difference in the US is that FEMA publishes every application, so the gap can be measured.

So we measured it, and built a way to close it.

What we builtPredictive + generative, end to end on LinuxONE

From 26 million records to a caseworker's next phone call.

1 · Cohort ruleVerified damage, denied, fixable reason. Rules, so every flag fits in one sentence.
2 · Snap ML modelWho lands here, from pre-decision facts only. Tested on 114 unseen disasters.
3 · Fairness auditRates with 95% intervals and adjusted odds ratios.
4 · Ranked callbacksPer disaster: loss, livability, reason, vulnerability. The weights are visible.
5 · Granite + RAGA cited note and script per household, grounded in FEMA's policy guide.
6 · DashboardStory, caseworker console, method. Served from a hardened container.

The trap we avoided: FEMA eligibility is nearly a rule, so a naive model reaches 0.99 AUC and learns nothing. We train only on verified-damage households and split by disaster.

Second Look6
Generative layerIBM's loan-approval lab, run in reverse

The lab explains why a bank said no. We find the families a system said no to, wrongly.

  1. Retrieve. FEMA's Individual Assistance Program and Policy Guide (IAPPG 1.1, ch. 3) is split into 89 passages and indexed as TF-IDF vectors. Each denial reason may only cite its own sections: Occupancy and Ownership, Identity, Insurance, Applicant Communication, plus the 60-day appeal rule.
  2. Generate locally. IBM Granite 3.3 2B Instruct runs in llama.cpp on the z17, from a big-endian GGUF. No household data leaves the machine.
  3. Verify before showing. Each citation must be a retrieved passage, each dollar amount must match the inspector's figure, and nothing may promise approval. Otherwise the note is rejected and the template script is shown.

On the z17: 50 notes covering the top 5 callbacks in each of the 10 largest disasters. All 50 passed the checks. Median 142s and 252 tokens per note on 3 shared vCPUs.

9
AI securedInnovation without exposure

Sensitive by nature, so nothing leaves the box.

Local LLM. Granite runs on the VM and listens only on 127.0.0.1. No third-party AI API ever sees a household.
Hardened container. Rootless Podman with a read-only root filesystem, all capabilities dropped, no-new-privileges, and a non-root UID.
Read-only data. The database is mounted :ro, and the API opens SQLite with mode=ro.
No inbound port. The dashboard binds to localhost. Caseworkers use an SSH tunnel with key-only auth, and the public demo uses an outbound Cloudflare tunnel to the read-only API. We replaced the public default Jupyter token.
No direct identifiers. OpenFEMA has no names, addresses or phone numbers. Households are opaque record IDs.
Guarded generation. Citations, dollar amounts and promises are checked in code before any note is shown.

What porting to s390x taught usBig-endian is real

Eight things that broke, and the fix that is now in code.

  1. pyarrow 19 reads numeric Parquet as null on big-endian. Every intermediate file is now Arrow IPC.
  2. 26M rows × 33 columns needed more than 16 GB in pandas. Cohort labeling streams batches, with a 364 MB peak.
  3. Snap ML's zDNN build needs the system libstdc++ (LD_PRELOAD).
  4. Snap ML heap-crashes on NaN, so missing values become -1.
  1. FEMA's CDN blocks the VM, so ingest runs on a little-endian host.
  2. GGUF models are little-endian; we use a big-endian Granite build.
  3. GCC 13 doesn't know z17's -march=arch15, so llama.cpp is built for z16.
  4. Without -mzvector, llama.cpp silently drops to scalar code: 1.2 vs 4.5 tokens/s.
Second Look11
Limits and ethicsTransparent decision reasoning

A starting point for outreach, never a decision.

  1. The data shows who was denied, not why each family's paperwork failed. A caseworker confirms everything on the call.
  2. The model learns FEMA's past decisions, biases included. We use it only to decide whom to call first, never to deny anyone.
  3. Adjusted odds ratios are associations with controls, not causal estimates.
  4. Granite drafts; people decide. Notes that fail a check are hidden, and the rules behind the ranking are shown in the open.
  5. Appeal windows for older disasters have closed. The value for those is measuring the gap; live use belongs in open disasters.
